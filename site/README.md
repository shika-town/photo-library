# SHIKA PHOTO LIBRARY（Ver1.6）

志賀町公式フォトライブラリーの実装です。ビルド不要の静的サイト（HTML / CSS / JavaScript）で、そのまま動きます。

**TOPページ／検索結果／スポット一覧／スポット詳細（9件）／写真詳細（65枚）／規約類4ページ／404** の計82ページを収録しています。

## 見る

`index.html` をダブルクリックするとブラウザで開きます。
ローカルサーバーで確認する場合は、このフォルダで次を実行してください。

```
python3 -m http.server 8000
```

## お問い合わせフォームの設置

現在はプレースホルダーです。Googleフォームを作成して差し替えてください。

1. [Googleフォーム](https://docs.google.com/forms/) で新しいフォームを作成します。項目の例：お名前／メールアドレス／ご用件の種類／お問い合わせ内容
2. 右上の「送信」→ `< >`（埋め込み）タブを開き、表示された `src="..."` のURLを控えます
3. 「回答」タブ → 右上の縦三点 → **「新しい回答についてのメール通知を受け取る」** をオンにします
   - 通知先を `shokan@town.shika.lg.jp` にするには、そのアドレスでフォームを作成するか、フォームの共同編集者に追加してください
4. `index.html` の `<div class="contact__placeholder">…</div>` を丸ごと次の1行に置き換えます

```html
<iframe class="contact__frame" src="【控えたURL】?embedded=true" loading="lazy" title="お問い合わせフォーム">読み込んでいます…</iframe>
```

回答はスプレッドシートに蓄積されるため、問い合わせの履歴管理もそのまま行えます。

### スポットの追加・編集

1. `data/spots.json` の `spots` 配列に項目を追加します（`id` がファイル名になります）
2. 写真を `assets/img/spots/` に置きます
   - ヒーロー `<id>-hero.jpg` 2000×1125（16:9）
   - サムネイル `<id>-01.jpg` 640×480（4:3）
   - 拡大用 `<id>-01-lg.jpg` 1400×1050（4:3）
3. HTMLを再生成します

```
python3 scripts/build-spots.py
```

`spots/*.html` は生成物です。直接編集しても次回の生成で上書きされるため、変更は `data/spots.json` か `scripts/build-spots.py` に対して行ってください。

### クレジット付きダウンロードの仕組み

設計書では Google Apps Script での画像生成を想定していましたが、**ブラウザ内の canvas で合成する方式**にしました。

1. 利用規約のモーダルを表示し、同意チェックが入るまでボタンを無効化
2. 元画像を canvas に描画し、右下に「© 志賀町」を半透明の帯付きで重ねる
3. JPEG（品質92）として書き出し、`P0010_bench.jpg` の形式で保存

クレジットの文字サイズと余白は画像の長辺に対する比率で決めているため、解像度が変わっても見え方が揃います。サーバー側の処理が不要なので、GitHub Pages のまま動き、Google Drive や Apps Script の設定も要りません。

文言やクレジットの位置は `assets/js/photo.js` の `stampCredit()` に集約しています。利用規約の本文は `scripts/build-photos.py` の `TERMS` です。

### ページの再生成

生成物は5つのスクリプトに分かれていますが、依存関係があるため通常はまとめて実行してください。

```
python3 scripts/build-all.py
```

| スクリプト | 入力 | 出力 |
|---|---|---|
| `build-data.py` | photos.json | assets/js/data.js |
| `build-library.py` | photos.json ＋ spots.json | data/library.json ／ assets/js/library-data.js |
| `build-spots.py` | spots.json | spots/*.html |
| `build-photos.py` | library.json | photos/*.html |
| `build-search.py` | ― | search.html |
| `build-pages.py` | スクリプト内の文面 | terms / privacy / credit / faq / 404.html |

ヘッダー・フッター・アイコンは `build-spots.py` に集約し、他のスクリプトはそれを読み込んでいます。ナビゲーションを変えるときは `build-spots.py` の `NAV` を直してください。

### 文面の修正方法

4ページ＋404の本文は、すべて `scripts/build-pages.py` の中にまとめてあります。ファイル冒頭の `UPDATED`（制定日）、`MAIL`、`DEPT`（担当部署名）を変えると全ページに反映されます。

FAQの項目は同ファイルの `FAQ` リスト、利用規約の各条文は `terms` の変数を直接編集してください。編集後に再生成します。

```
python3 scripts/build-pages.py
```

### 404ページについて

GitHub Pages は、存在しないURLにアクセスがあったとき `404.html` を自動的に表示します。

ただしリポジトリ名付きのURL（`https://ユーザー名.github.io/リポジトリ名/`）で公開する場合、深い階層で404になるとページ内のリンクがずれます。気になる場合は `404.html` 内のリンクを `/リポジトリ名/index.html` のような形に書き換えてください。

### 写真の自動リサイズ

| 用途 | サイズ |
|---|---|
| ヒーロー | 2000×1125 |
| トップの新着 | 1080×840 |
| ギャラリー | 640×480 |
| 拡大・ダウンロード | 1400×1050 |

### 動作確認の結果

現在のサイト内容をシートに書き出し、それを読み込み直してJSONを再生成する往復テストを行いました。
**9スポットすべてで、名称・読み・エリア・住所・キャッチ・説明文・タグ・基本情報・出典・写真枚数が一致**します。

トップページの新着写真の並び、シーン6枚、季節4枚も再現されます。写真のキャプションは、トップとスポットで
同じ元写真を使っていた6枚を1枚に統合したため、その分だけ文言が変わります（重複表示の解消）。

### 初回の書き出しについて

`export-sheet.py` には、初回だけ必要な重複整理（`DEDUP_DROP`）が入っています。これは手作業で作った現在の
コンテンツをシートに移すためのもので、**一度シート運用が始まったら export-sheet.py を再実行する必要はありません**。
以降はシートが正としてください。

**すべて `data/photos.json` で管理しています。** カードの枚数・並び順は配列の要素数と順番がそのまま反映されます。

編集したら、`data.js`（`file://` で開いたとき用のコピー）を再生成してください。

```
python3 scripts/build-data.py
```

## 写真の差し替え

`assets/img/` の同名ファイルを上書きすれば、JSONを触らずに差し替わります。推奨サイズは次のとおりです。

| 用途 | サイズ | 比率 |
|---|---|---|
| Hero | 2400×1350 | 16:9 |
| 人気スポット | 1200×800 | 3:2 |
| 新着写真 | 1080×840 | 9:7 |
| 季節 | 800×600 | 4:3 |

切り抜き位置を調整したい場合は、CSSに `object-position` を追加します。

```css
.spot-card__media img { object-position: center 30%; }
```
